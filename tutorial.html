What we are making (no jargon yet)

You already know ChatGPT. You type. It answers. The problem: ChatGPT does not know your product. It was trained on the public internet. It has never read your refund policy. If you ask anyway, it will often invent a policy that sounds real.

This project is a small Python program that sits in front of GPT and does extra work before GPT is allowed to talk:

  1. It looks in your files for the few paragraphs that match the question.
  2. It pastes those paragraphs into a sheet of instructions GPT must follow.
  3. Only then does GPT write a sentence.
  4. If you say “book a demo,” it can run a Python function instead of pretending.
  5. If you say “my name is Sam,” it writes that down so the next message still knows.

Those five jobs have names. We will use them for the rest of the page, so here they are in dummy language:

  • RAG — Retrieval-Augmented Generation. Three steps: look up (retrieve), paste into the prompt (augment), write (generate). GPT is only the last step.
  • OKF — Open Knowledge Format. How we save each looked-up piece as a markdown file with a label on top, so a human can still open it.
  • LangGraph — A library that runs our steps in order, and can loop when GPT asks to run a function.
  • tool — A Python function GPT is allowed to call, such as book_demo. Talking is not the same as running code.
  • memory — Facts about this person (“User’s name is Sam”), stored in a tiny database. This is not company knowledge. Company knowledge lives in files.
  • embedding / vector — A long list of numbers that means “what this paragraph is about.” Similar meaning → similar numbers. That is how search can match “refund” to “money back.”
  • chunk — A small page cut from a bigger document, about 800 characters. We search chunks, not whole books, so one question does not drag an entire source file into the prompt.

GPT is only the writer. The rest of the code is the desk, the filing cabinet, and the recipe card.

The folders — what lives where, and why

Company knowledge is whatever files that company already has. We do not ship a sample handbook. We do not assume sections named Product, Refunds, or Billing. You drop their files in knowledge/raw/ and ingest. If the folder is empty, skip ingest — chat still works; GPT just has no company pages to look up.

1. knowledge/raw/ — the incoming pile You drop original files here: Word (.docx), markdown (.md), or plain text (.txt). Any names, any headings. “Raw” means “not processed yet.” The bot does not chat from this folder. A function named ingest reads the files, then writes new files into the next folder. Empty is allowed: then there is no company truth, and GPT should say it does not know.
2. knowledge/okf/ — the labeled cabinet After ingest, each source becomes one OKF Document here (the whole file, labeled), and many OKF Chunks under knowledge/okf/chunks/ (the pages). Each chunk knows its parent document, its heading, and the original filename. RAG searches chunks. You can still open them in any editor. Chroma cannot be emailed to a teammate; these files can.
3. data/chroma/ — the card catalog Chroma is a local search index. It stores the list of numbers (embedding) for each chunk. When someone asks a question, we turn it into numbers and ask Chroma for the nearest chunks. Do not edit this folder by hand. Rebuild it by running ingest again.
4. data/bot.db — the conversation notebook A SQLite file (one file that acts like a tiny spreadsheet). Three tables: messages (what you and the bot said), facts (memories about the person), actions (a demo was booked). Company documents do not belong here. Those stay in OKF.

The files you will type, and what each one is for:

  • bot.py — The whole engine. Almost every function lives here. Other files only call this.
  • ingest.py — A tiny starter. You point it at a file path. It calls ingest() inside bot.py. It does not search or talk.
  • chat.py — A tiny front desk. You type in the terminal. It calls reply() inside bot.py. It does not know about Chroma.
  • prompt.md — English instructions GPT must obey. Two holes, {knowledge} and {facts}, get filled every turn by Python.
  • .env — Your secret OpenAI key. Python reads it. Never put the key in bot.py.
  • .env.example — The same variable names with a blank key, so someone else knows what to fill in.
  • .gitignore — A list of files git should not upload: the key, the database, generated OKF.
  • knowledge/raw/ — Empty until a company drops their own .md / .txt / .docx files here. Not a prompt. Not required to chat.
  • requirements.txt — The Python libraries to install.

Company files are optional — and they are not a prompt

prompt.md is how GPT behaves. A file in knowledge/raw/ is what is true about that company. Same markdown clothes, different job. We do not create a fake handbook. When you have a real doc, drop it in knowledge/raw/ (any name) and run ingest. Headings in that file become chunks. If you never ingest, RAG’s cabinet is empty and the bot should say it does not know company facts. Memory, tools, and chat still work.

Ingest copies meaning into OKF and Chroma. The original in raw/ stays. If you edit the original and do not ingest again, the index is stale.

The three ideas, slower

RAG — why not dump the whole file into GPT?

You could paste an entire source file into the prompt every time. That costs more (GPT charges per token, which is roughly per word), and the useful sentence gets lost in noise. RAG’s job: pick about 5 small pages that match this question, paste only those, then generate.

How “match” works here: an embedding model named text-embedding-3-small (OpenAI) turns a paragraph into numbers. Chroma stores those numbers on your disk. If embeddings fail (no API key, empty index), we fall back to counting overlapping words. Still a lookup. Dumber matching. Close synonyms may not match in the fallback.

Lookup without paste is a search you never use. Paste without lookup is guessing. Both together are RAG.

OKF — why not only Chroma?

Chroma is a black box of numbers. You cannot open it and edit paragraph 4. After ingest, a chunk file looks like this:

Example of a generated chunk (you do not type this; ingest writes it from whatever file you gave it)
---
type: Chunk
title: Hours
parent: office-guide
section: Hours
source_file: office-guide.md
---

The office is open Monday to Friday, 9 to 5.
  • The block between --- lines — Called frontmatter. It is YAML: a labeled list. type is Document or Chunk. parent is which document this page came from. section is the heading in that company’s file. source_file is the original filename.
  • The paragraph under the second --- — The actual text GPT will read if retrieve picks this chunk.
  • Why parent exists — So a citation can say office-guide#Hours instead of a random filename. That is what chat.py prints after sources>. The names come from the file you ingested, not from this tutorial.

LangGraph — why not one giant function?

You could write: look up, call GPT, maybe run a tool, save. That works until GPT says “I need to call book_demo.” Then you must run the function, send the result back to GPT, and let GPT write “You’re booked.” That is a loop. LangGraph is a library for “do step A, then B, and sometimes go back.”

  • node — A Python function we register on the graph. It receives the current state (a backpack of data) and returns the fields it wants to change.
  • edge — An arrow: after this node, always go there.
  • conditional edge — An arrow that asks a question. Ours asks: did GPT request a tool? If yes, go to tools. If no, go to save.
  • state — The backpack. Keys like message, knowledge, facts, reply. Every node reads and writes this one dict. Nobody passes ten arguments around.
The recipe we will wire
flowchart TD
  START([START]) --> retrieve
  retrieve["retrieve: lookup + memory"] --> agent["agent: GPT"]
  agent -->|GPT wants a tool| tools["tools: run book_demo etc"]
  tools --> agent
  agent -->|GPT is done talking| save["save: store reply + facts"]
  save --> END([END])

One user message can loop agent → tools → agent, then save once.

prompt.md — GPT’s manners sheet

Every GPT call can include a system message: instructions that are not the user’s question. Ours live in a markdown file so you can change the voice without touching Python. Create prompt.md now, before bot.py, because load_prompt() will read it.

Put this in your file · markdown — prompt.md
You are a helpful assistant for this product.

How to talk:
- Be clear, warm, and direct.
- Keep answers short unless the person asks for detail.
- Do not invent facts about the product, company, or policies.
- If the knowledge below does not contain the answer, say you do not know.
- Use stored facts about this person when it helps.
- You can book a demo, save a fact, or hand the chat to a human.

Knowledge from the company files:
{knowledge}

Facts we already know about this person:
{facts}
  • You are a helpful assistant... — Role. GPT tries to stay in this character.
  • Do not invent facts... — The most important rule. Without it, GPT would rather sound confident than honest.
  • If the knowledge below does not contain the answer, say you do not know — Ties the model to RAG. Empty knowledge should produce a refusal, not a made-up policy.
  • {knowledge} — A placeholder. You never type the chunks into this file. load_prompt() replaces this with retrieved paragraphs every turn. The spelling must match exactly, including the braces.
  • {facts} — The other placeholder. Replaced with memory like “User’s name is Sam.”
  • You can book a demo... — A hint that tools exist. The real tool list is still bound in Python; this only tells GPT it is allowed to try.

If you add “Always answer in simple English” here and run chat, the voice changes. That is the proof that this file is live.

bot.py from the top — names we reuse everywhere

Create bot.py. This first block is not a function. It is imports (borrowing other people’s code), paths (where files live), and knobs (numbers you can tune). Every later function uses these names.

Why we import each thing:

  • json — Turn a Python dict into text for the actions table, and parse GPT’s fact JSON back into a dict.
  • os — Read environment variables such as the API key.
  • re — Regular expressions: pull words out of a question for the fallback search.
  • sqlite3 — Python’s built-in database. No extra server to install.
  • uuid — Random ids so each database row has a unique name.
  • Path — Safer file paths than raw strings. ROOT / "data" works on Mac and Windows.
  • Annotated, TypedDict — Describe the shape of state. Annotated tells LangGraph how to merge the messages list (append, do not replace).
  • yaml — Read and write OKF labels.
  • load_dotenv — Load .env as soon as bot.py is imported, before any function runs.
  • Chroma, Document — The vector store, and the object we insert into it.
  • SystemMessage, HumanMessage, AIMessage — The three roles in a GPT transcript: instructions, user, assistant.
  • tool — Decorator that turns a function into something GPT can call. The line looks like @tool above def.
  • ChatOpenAI, OpenAIEmbeddings — GPT and the embedding model.
  • StateGraph, START, END, add_messages, ToolNode — LangGraph: the graph, the start/end markers, how messages merge, and a ready-made node that runs tools.

Why each path and knob exists:

  • ROOT — The folder that contains bot.py. All other paths hang off this so the code does not care what you named the project or where you put it.
  • load_dotenv(ROOT / ".env") — Runs once at import. After this, os.getenv can see OPENAI_API_KEY.
  • RAW_DIR, OKF_DIR, CHUNK_DIR, DATA_DIR, CHROMA_DIR, DB_PATH, PROMPT_PATH — One name per folder or file. Later functions use these names instead of repeating strings. If you renamed a folder, you would change it here once.
  • HISTORY_LIMIT = 20 — Only the last 20 chat lines go to GPT. Older lines stay in the database but are not sent, so the prompt does not grow forever (and cost more each turn).
  • FACT_LIMIT = 20 — If we have 20 facts or fewer, send them all. If more, filter. See relevant_facts.
  • RAG_K = 5 — How many chunks retrieve returns. Raise it if answers miss context. Lower it if prompts feel bloated.
  • CHUNK_SIZE = 800 — Max characters in one chunk. Bigger = fewer chunks, worse targeting. Smaller = more fragments.
  • The mkdir loop — Creates empty folders on first run so ingest and Chroma do not crash because a directory is missing. parents=True also creates knowledge/ if needed. exist_ok=True means “do not error if it already exists.”

Talking to GPT and to the notebook

llm() — the phone line to GPT

Why this function existsEvery place that needs GPT (the agent, the fact extractor) should not copy API-key code. One function returns a ready client. If we later change model or temperature, we change one line.
Put this in your file · python — bot.py
def llm():
    return ChatOpenAI(model=OPENAI_MODEL, api_key=OPENAI_API_KEY or None, temperature=0)
  • ChatOpenAI(...) — LangChain’s wrapper around OpenAI’s chat API. You call .invoke(messages) on what this returns.
  • model=OPENAI_MODEL — Uses the name from .env, default gpt-4o-mini.
  • api_key=OPENAI_API_KEY or None — If the key is the empty string "", pass None instead. The library then looks at the environment itself.
  • temperature=0 — How random GPT is. 0 means pick the most likely next words. We want a consistent support bot, not a poet.

db() — open the notebook

WhySQLite is a single file, but we still need tables (like sheets). db() opens data/bot.db and creates three tables if this is the first run. Other functions call db() whenever they need to read or write, then they close the connection. We do not keep one global connection forever.
Put this in your file · python — bot.py
def db():
    DATA_DIR.mkdir(parents=True, exist_ok=True)
    conn = sqlite3.connect(DB_PATH)
    conn.row_factory = sqlite3.Row
    conn.executescript(
        """
        CREATE TABLE IF NOT EXISTS messages (
            id TEXT PRIMARY KEY, role TEXT, content TEXT, created_at TEXT
        );
        CREATE TABLE IF NOT EXISTS facts (
            id TEXT PRIMARY KEY, fact TEXT UNIQUE, created_at TEXT
        );
        CREATE TABLE IF NOT EXISTS actions (
            id TEXT PRIMARY KEY, kind TEXT, payload TEXT, created_at TEXT
        );
        """
    )
    return conn
  • DATA_DIR.mkdir(...) — Create data/ if someone deleted it.
  • sqlite3.connect(DB_PATH) — Open or create the file. Returns a connection we name conn.
  • conn.row_factory = sqlite3.Row — Let us write row["fact"] instead of row[0]. Names beat positions.
  • CREATE TABLE IF NOT EXISTS — If the table already exists, do nothing. Safe to call every time.
  • messages — One row per chat line. role is the text user or assistant. content is what they said.
  • facts — One row per memory. fact TEXT UNIQUE means we cannot store the same sentence twice.
  • actions — One row per tool side-effect. kind is book_demo or handoff. payload is JSON details (topic, time).
  • return conn — The caller must commit() (save) and close() (unlock the file).

now() — timestamps

WhyEvery row wants to know when it was written, so history() can sort. We use UTC so two machines do not disagree about timezones.
Put this in your file · python — bot.py
def now():
    from datetime import datetime, timezone

    return datetime.now(timezone.utc).isoformat()
  • Import inside the function — Keeps the top of the file shorter. Fine here.
  • isoformat() — Returns text like 2026-10-26T10:00:00+00:00. SQLite stores it as TEXT. Good enough to sort.

add_message(role, content) — save one line of chat

WhyIf we do not save, the next turn GPT will not know what was said. This writes one row. role tells us who spoke.
Put this in your file · python — bot.py
def add_message(role: str, content: str):
    conn = db()
    conn.execute(
        "INSERT INTO messages VALUES (?, ?, ?, ?)",
        (uuid.uuid4().hex, role, content.strip(), now()),
    )
    conn.commit()
    conn.close()
  • role — The string "user" or "assistant". Not a Python class. Just text in the table.
  • content.strip() — Remove accidental spaces at the ends.
  • uuid.uuid4().hex — A random 32-character id. Primary key. We never reuse it.
  • The four ? in INSERT — Placeholders. The tuple that follows fills them in order. This avoids quoting bugs and SQL injection.
  • commit() — Actually write to disk. Without this, the row vanishes when we close.
  • close() — Free the file lock so the next call to db() can open it.

history() — last 20 lines, oldest first

WhyGPT needs recent conversation to understand follow-ups like “what about the other one?” We do not send the entire database. We send HISTORY_LIMIT lines. Oldest first because a chat transcript reads top to bottom.
Put this in your file · python — bot.py
def history():
    conn = db()
    rows = conn.execute(
        """
        SELECT * FROM (
            SELECT * FROM messages ORDER BY created_at DESC LIMIT ?
        ) ORDER BY created_at ASC
        """,
        (HISTORY_LIMIT,),
    ).fetchall()
    conn.close()
    return [{"role": r["role"], "content": r["content"]} for r in rows]
  • Inner SELECT ... DESC LIMIT ? — Take the newest 20. They come out newest-first, which is the wrong order for GPT.
  • Outer ORDER BY created_at ASC — Flip them. Now the first dict is the oldest of those 20.
  • The ? is filled with (HISTORY_LIMIT,) — The trailing comma makes a one-item tuple, which sqlite3 requires.
  • Return value — A list of dicts like [{"role": "user", "content": "hi"}]. node_agent will turn these into HumanMessage / AIMessage objects.

all_facts / add_fact / forget_fact — long-term memory

Why three functionsMemory is a list of freeform sentences, not a profile form with “name” and “email” boxes. We need: read them all, add one if new, delete if the person corrects themselves. Split into three so tools and node_save can each call what they need.
Put this in your file · python — bot.py
def all_facts() -> list[str]:
    conn = db()
    rows = conn.execute("SELECT fact FROM facts ORDER BY created_at").fetchall()
    conn.close()
    return [r["fact"] for r in rows]
  • SELECT fact ... ORDER BY created_at — Oldest first, stable list.
  • Return value — A list of strings, for example ["User’s name is Sam"].
Put this in your file · python — bot.py
def add_fact(fact: str) -> str | None:
    text = " ".join(fact.strip().split())
    if not text:
        return None
    conn = db()
    exists = conn.execute("SELECT 1 FROM facts WHERE lower(fact)=lower(?)", (text,)).fetchone()
    if exists:
        conn.close()
        return None
    conn.execute("INSERT INTO facts VALUES (?, ?, ?)", (uuid.uuid4().hex, text, now()))
    conn.commit()
    conn.close()
    return text
  • " ".join(fact.strip().split()) — Collapse weird spacing so “Sam” and “ Sam ” become the same text.
  • if not text: return None — Do not store empty strings. None means “we stored nothing.”
  • lower(fact)=lower(?) — Duplicate check that ignores capital letters.
  • return None vs return text — None means “already there.” The save_fact tool uses that to say “Already stored.”
Put this in your file · python — bot.py
def forget_fact(text: str) -> list[str]:
    needle = text.strip().lower()
    removed = []
    conn = db()
    for row in conn.execute("SELECT id, fact FROM facts").fetchall():
        if needle in row["fact"].lower() or row["fact"].lower() in needle:
            conn.execute("DELETE FROM facts WHERE id=?", (row["id"],))
            removed.append(row["fact"])
    conn.commit()
    conn.close()
    return removed
  • needle — The search string, lowercased. We named it needle because we search for it inside haystacks (the stored facts).
  • needle in fact or fact in needle — If they say “not Sam”, we match a stored fact that contains Sam, or a fact fully contained in their sentence. A bit fuzzy on purpose.
  • Return value — The list of strings we deleted, useful if you ever print debug info.

OKF helpers — write labels, read labels

write_okf / parse_okf

Why a pairWe need one way to write a labeled markdown file and one way to read it back. Ingest writes. Retrieve and index read. If you change the format, you change these two only.
Put this in your file · python — bot.py
def write_okf(path: Path, meta: dict, body: str):
    path.parent.mkdir(parents=True, exist_ok=True)
    front = yaml.safe_dump(meta, sort_keys=False, allow_unicode=True).strip()
    path.write_text(f"---\n{front}\n---\n\n{body.strip()}\n", encoding="utf-8")
  • path — Where to write, e.g. knowledge/okf/chunks/office-guide-hours-01.md.
  • meta — A Python dict that becomes YAML. Example keys: type, title, parent.
  • body — The paragraph(s) under the frontmatter.
  • yaml.safe_dump — Dict → YAML text. sort_keys=False keeps our field order. allow_unicode=True keeps accents.
  • The f-string with --- — The OKF sandwich: dashed line, YAML, dashed line, blank line, body.
Put this in your file · python — bot.py
def parse_okf(path: Path) -> tuple[dict, str]:
    text = path.read_text(encoding="utf-8")
    if not text.startswith("---"):
        return {}, text.strip()
    parts = text.split("---", 2)
    if len(parts) < 3:
        return {}, text.strip()
    return yaml.safe_load(parts[1]) or {}, parts[2].strip()
  • If the file does not start with --- — Treat everything as body, empty dict for meta. Defensive: a plain markdown file still “works.”
  • split("---", 2) — Cut into at most 3 pieces: before, yaml, after. The 2 means “split twice.”
  • yaml.safe_load(parts[1]) — YAML text → dict. or {} if YAML was empty.
  • Return value — A tuple (meta, body). Callers write meta, body = parse_okf(path).

slug(text) — safe filenames

WhyWindows and Mac hate filenames like “Office Guide!”. slug turns any heading into lowercase letters, numbers, and hyphens: office-guide. Used when we name OKF files.

chunk_text(body) — tear the book into pages

WhyOne embedding for a long source file would mix unrelated topics. Search would always drag the whole file. We split on markdown headings first. If a section is still longer than CHUNK_SIZE (800 characters), we pack paragraphs until the budget is full.
Put this in your file · python — bot.py
def chunk_text(body: str) -> list[tuple[str, str]]:
    sections: list[tuple[str, list[str]]] = [("", [])]
    for line in body.splitlines():
        if line.startswith("#"):
            sections.append((line.lstrip("#").strip(), []))
        else:
            sections[-1][1].append(line)
    chunks = []
    for heading, lines in sections:
        text = "\n".join(lines).strip()
        if not text:
            continue
        if len(text) <= CHUNK_SIZE:
            chunks.append((heading, text))
            continue
        current = ""
        for para in text.split("\n\n"):
            piece = para.strip()
            if not piece:
                continue
            if current and len(current) + len(piece) > CHUNK_SIZE:
                chunks.append((heading, current))
                current = piece
            else:
                current = f"{current}\n\n{piece}".strip() if current else piece
        if current:
            chunks.append((heading, current))
    return chunks
  • body — The whole document as one string, already extracted from Word or markdown.
  • sections starts as [("", [])] — Text before the first heading still has a home (empty heading name, empty list of lines).
  • if line.startswith("#") — New section. Strip the # marks to get the heading name.
  • else: append line — Body lines belong to the latest heading.
  • If len(text) <= CHUNK_SIZE — Short section → keep together. Better for meaning.
  • Split on blank lines — Paragraphs. Add them to current until adding one more would exceed 800 characters, then start a new chunk with the same heading.
  • Return value — A list of pairs (heading, text). Ingest writes one OKF file per pair.

Example: a source file with three ## headings usually becomes three chunks. A question about one heading can then retrieve that page without the others.

def index_chunks(paths: list[Path]) -> int:
    if not OPENAI_API_KEY:
        return len(paths)
    import chromadb

    client = chromadb.PersistentClient(path=str(CHROMA_DIR))
    try:
        client.delete_collection("knowledge")
    except Exception:
        pass
    docs = []
    for path in paths:
        meta, body = parse_okf(path)
        if not body:
            continue
        docs.append(
            Document(
                page_content=body,
                metadata={
                    "source": f"{meta.get('parent', path.stem)}#{meta.get('section', '')}".strip("#"),
                    "title": meta.get("title", path.stem),
                },
            )
        )
    if docs:
        chroma().add_documents(docs)
    return len(docs)

  • if not OPENAI_API_KEY: return len(paths) — Cannot embed without a key. Skip Chroma. retrieve() will use word overlap later.
  • delete_collection("knowledge") — Throw away the old index. The except is because the first run has nothing to delete.
  • parse_okf(path) — Read labels + body from each chunk file.
  • Document(page_content=body, metadata=...) — LangChain’s shape. page_content is searchable text. metadata["source"] is the citation string parent#section.
  • chroma().add_documents(docs) — This is the moment OpenAI turns each body into a vector and Chroma saves it.
  • Return value — How many documents we indexed. ingest.py prints this.

retrieve(question) — the R in RAG

WhyThis is the lookup. Input: the user’s sentence as a string. Output: a list of dicts like [{"source": "office-guide#Hours", "body": "..."}], length up to 5. Those dicts will be pasted into prompt.md. If this function always returned [], GPT would never see the company files. That is also valid: you can chat with no knowledge ingested.
Put this in your file · python — bot.py
def retrieve(question: str) -> list[dict]:
    if OPENAI_API_KEY:
        try:
            hits = chroma().similarity_search(question, k=RAG_K)
            return [
                {
                    "source": (d.metadata or {}).get("source", ""),
                    "body": d.page_content,
                }
                for d in hits
            ]
        except Exception:
            pass
    words = {w for w in re.findall(r"[a-z0-9]+", question.lower()) if len(w) > 2}
    scored = []
    for path in sorted(CHUNK_DIR.glob("*.md")):
        meta, body = parse_okf(path)
        hay = f"{meta.get('title', '')} {meta.get('parent', '')} {body}".lower()
        score = sum(1 for w in words if w in hay)
        if score:
            scored.append((score, {"source": f"{meta.get('parent', path.stem)}#{meta.get('section', '')}".strip("#"), "body": body}))
    scored.sort(key=lambda item: item[0], reverse=True)
    return [item[1] for item in scored[:RAG_K]]
  • question — Whatever the human typed this turn, e.g. “What are the office hours?”
  • similarity_search(question, k=RAG_K) — Embed the question, find the 5 nearest chunk vectors. Returns LangChain Document objects.
  • We map them to source and body — We only keep what the prompt needs.
  • except: pass — If Chroma is empty or the network fails, fall through to word overlap instead of crashing the whole chat.
  • words = {w for w in re.findall(...) if len(w) > 2} — Fallback: unique words longer than 2 letters. “is” and “a” are ignored because they match everything.
  • score — How many of those words appear in title + parent + body. A chunk that contains two of the question’s words scores 2.
  • sort reverse, take [:RAG_K] — Best first, keep 5.

If you ingested a file that mentions hours, a question about hours should return that chunk. The source string is parent#section from the OKF labels — names taken from their file, not from this tutorial. That string is what chat.py prints after sources>.

A common confusionChroma does not answer the question. It only ranks chunks. GPT answers. If a wrong chunk is in the top 5, GPT may still quote it. Retrieval quality is most of RAG quality.

Fill the prompt, pick facts

load_prompt — the A in RAG (augment)

Whyprompt.md has holes. This function reads the file and fills them. Without it, GPT would see the literal text {knowledge} and none of the retrieved pages.
Put this in your file · python — bot.py
def load_prompt(knowledge: list[dict], facts: list[str]) -> str:
    template = PROMPT_PATH.read_text(encoding="utf-8")
    knowledge_text = "\n\n".join(f"[{item['source']}]\n{item['body']}" for item in knowledge) or "No matching knowledge yet."
    facts_text = "\n".join(f"- {f}" for f in facts) or "No stored facts yet."
    return template.replace("{knowledge}", knowledge_text).replace("{facts}", facts_text)
  • knowledge — The list retrieve produced.
  • facts — The list relevant_facts produced.
  • Join chunks as [source] then body — GPT can see which chunk a paragraph came from.
  • or "No matching knowledge yet." — If retrieve returned []. Honest empty state. Combined with “do not invent,” GPT should refuse.
  • .replace("{knowledge}", ...).replace("{facts}", ...) — Simple string replace. The placeholders in prompt.md must match these exact spellings, including braces.
  • Return value — The full system prompt as one string. node_agent wraps this in SystemMessage.

WhyIf Sam told us 3 facts, send all 3. If the table grew to 400, sending all of them would drown the prompt. Then we rank by word overlap with the question and keep 5. Hybrid: cheap when small, filtered when large. We did not stand up a second Chroma collection for memory. For this bot, that would be extra ceremony.
Put this in your file · python — bot.py
def relevant_facts(question: str) -> list[str]:
    facts = all_facts()
    if len(facts) <= FACT_LIMIT:
        return facts
    words = {w for w in re.findall(r"[a-z0-9]+", question.lower()) if len(w) > 2}
    ranked = sorted(facts, key=lambda f: sum(1 for w in words if w in f.lower()), reverse=True)

  • all_facts() — Read the whole table.
  • if len(facts) <= FACT_LIMIT: return facts — The common case. No scoring.
  • Else rank by how many question-words appear in the fact — Same idea as retrieve’s fallback.
  • return ranked[:RAG_K] — Reuse 5. Good enough here.

The graph nodes — four workers

Each of these is a function LangGraph will call. They all take state (the backpack) and return a dict of updates. LangGraph merges that dict into state. You do not return the whole backpack.

def node_agent(state: State) -> dict:
    model = llm().bind_tools(TOOLS)
    existing = state.get("messages") or []
    if existing:
        return {"messages": [model.invoke(existing)]}
    prompt = [SystemMessage(content=load_prompt(state.get("knowledge") or [], state.get("facts") or []))]
    for item in state.get("history") or []:
        if item["role"] == "assistant":
            prompt.append(AIMessage(content=item["content"]))
        else:
            prompt.append(HumanMessage(content=item["content"]))
    prompt.append(HumanMessage(content=state["message"]))
    return {"messages": prompt + [model.invoke(prompt)]}
  • llm().bind_tools(TOOLS) — A GPT client that is allowed to emit tool calls. bind_tools does not run the tools. It only advertises them.
  • existing = state.get("messages") or [] — If we already have a transcript this turn, we are on a later loop. .get returns None if the key is missing; or [] turns that into an empty list.
  • if existing: invoke(existing) — Second (or third) visit. The list already contains the tool result from ToolNode.
  • SystemMessage(load_prompt(...)) — First visit. Manners + chunks + facts.
  • Replay history as AIMessage or HumanMessage — So GPT knows earlier turns.
  • Append HumanMessage(state["message"]) — The new question last.
  • Return prompt + [model.invoke(prompt)] — Store both the prompt and GPT’s reply. GPT’s reply might be text, or a tool call, or both.

        return "tools"

  • last = messages[-1] — GPT’s latest output. [-1] means the last item in the list.
  • getattr(last, "tool_calls", None) — If GPT requested functions, this is a non-empty list. If GPT just spoke, it is empty or missing. getattr is used because not every message object has that attribute.
  • Return "tools" or "save" — Must match the names we registered in get_engine. A typo here silently breaks the graph.

node_save

Why lastThe user needs a sentence. The database needs both lines. Memory needs any new facts. chat.py needs a control flag. This node does all of that after GPT is done looping with tools.
Put this in your file · python — bot.py
def node_save(state: State) -> dict:
    messages = state.get("messages") or []
    reply = ""
    used_handoff = False
    for item in reversed(messages):
        if getattr(item, "name", "") == "request_handoff":
            used_handoff = True
        if isinstance(item, AIMessage) and item.content and not getattr(item, "tool_calls", None):
            reply = item.content if isinstance(item.content, str) else str(item.content)
            break
    text = f"{state.get('message', '')} {reply}".lower()
    control = "continue"
    if used_handoff or "hand off" in text or "talk to a human" in text:
        control = "handoff"
    elif any(word in text for word in ("goodbye", "bye", "that's all", "thats all")):
        control = "end"

    add_message("user", state.get("message", ""))
    add_message("assistant", reply)

    try:
        extracted = llm().invoke(
            [
                SystemMessage(content="Extract facts about the person. Return JSON only: {\"facts\": [], \"forget\": []}. No company knowledge."),
                HumanMessage(content=f"User: {state.get('message', '')}\nAssistant: {reply}"),
            ]
        )
        payload = json.loads(extracted.content or "{}")
    except Exception:
        payload = {}
    for item in payload.get("forget") or []:
        forget_fact(str(item))
    for item in payload.get("facts") or []:
        add_fact(str(item))
    return {"reply": reply or "I am here when you want to continue.", "control": control, "facts": all_facts()}
  • Walk messages reversed — The final user-facing text is the last AIMessage that has content and no tool_calls. Tool-call messages are not for the user.
  • used_handoff — True if a message named request_handoff appears. Then control becomes handoff even if the wording is polite.
  • text = user message + reply, lowercased — Simple keyword checks for goodbye / talk to a human.
  • control starts as continue — The normal case: chat.py keeps looping.
  • add_message user then assistant — Persist this turn. Next history() will include it.
  • Second llm().invoke for JSON facts — A dedicated mini-prompt: extract person facts only, not company policy. So “My name is Sam” is stored even if GPT never called save_fact.
  • Forget then add — Apply corrections first, then new facts.
  • Return reply, control, facts — These keys are what reply() will pick out of the graph result. If reply is empty, we send a fallback sentence so the user is never staring at a blank line.

Put this in your file · python — bot.py
def get_engine():
    global ENGINE
    if ENGINE is None:
        graph = StateGraph(State)
        graph.add_node("retrieve", node_retrieve)
        graph.add_node("agent", node_agent)
        graph.add_node("tools", ToolNode(TOOLS))
        graph.add_node("save", node_save)
        graph.add_edge(START, "retrieve")
        graph.add_edge("retrieve", "agent")
        graph.add_conditional_edges("agent", route_agent, {"tools": "tools", "save": "save"})
        graph.add_edge("tools", "agent")
        graph.add_edge("save", END)
        ENGINE = graph.compile()
    return ENGINE

  • add_node("tools", ToolNode(TOOLS)) — We did not write a runner. ToolNode looks at tool_calls, runs the matching Python function, appends the result to messages.
  • add_edge(START, retrieve) — Every run begins here.
  • add_edge(retrieve, agent) — Always. No skipping lookup.
  • add_conditional_edges(agent, route_agent, {tools, save}) — After agent, call route_agent. Map its return value to a node.
  • add_edge(tools, agent) — The loop. After a tool runs, GPT speaks again.
  • add_edge(save, END) — Stop. invoke() returns the full state.

def ingest(path: str | Path) -> dict:
    """Turn a file (or a folder of files) into searchable knowledge."""
    target = Path(path).expanduser().resolve()
    if not target.exists():
        raise FileNotFoundError(f"Nothing at that path: {target}")

    allowed = {".md", ".txt", ".docx"}
    if target.is_dir():
        sources = [p for p in target.iterdir() if p.is_file() and p.suffix.lower() in allowed]
    else:
        sources = [target]
    sources = [p for p in sources if p.suffix.lower() in allowed]
    if not sources:
        raise FileNotFoundError(
            "No .md, .txt, or .docx at that path. Put any company files in knowledge/raw/ "
            "or pass a path. Chat still works without ingest; there will just be no company knowledge."
        )

    for old in OKF_DIR.glob("*.md"):
        old.unlink()
    for old in CHUNK_DIR.glob("*.md"):
        old.unlink()

    chunk_paths = []
    for source in sources:
        body = _read_source(source)
        if not body:
            continue
        concept_id = slug(source.stem)
        write_okf(
            OKF_DIR / f"{concept_id}.md",
            {
                "type": "Document",
                "title": source.stem,
                "source_file": source.name,
            },
            body,
        )
        for index, (section, text) in enumerate(chunk_text(body), start=1):
            chunk_path = CHUNK_DIR / f"{concept_id}-{slug(section) or 'part'}-{index:02d}.md"
            write_okf(
                chunk_path,
                {
                    "type": "Chunk",
                    "title": section or source.stem,
                    "parent": concept_id,
                    "section": section,
                    "source_file": source.name,
                },
                text,
            )
            chunk_paths.append(chunk_path)

    indexed = index_chunks(chunk_paths)
    return {"files": len(sources), "chunks": indexed}
  • path — String or Path. expanduser() understands ~. resolve() makes it absolute.
  • If not exists → FileNotFoundError — Beginner trap: FILE_PATH pointed at a machine that is not yours. Fix the path.
  • allowed = {.md, .txt, .docx} — Anything else is ignored. This project does not parse PDFs.
  • Folder vs file — A folder: every allowed file inside (not nested subfolders). A file: a list of one.
  • unlink old OKF — Delete previous documents and chunks. Clean rebuild.
  • concept_id = slug(source.stem) — stem is the filename without extension. office-guide.md → office-guide.
  • Write one Document OKF — Full body in knowledge/okf/. Human-readable backup of the source.
  • For each chunk: write a Chunk OKF — parent=concept_id ties the page to the document. section is the heading from that file. The filename includes a 01, 02 counter so two headings with the same name cannot clash.
  • index_chunks(chunk_paths) — Build Chroma from those chunk files.
  • Return {files, chunks} — Counts. ingest.py prints them so you know it worked.

bot.py is complete. Two tiny files still call it.

ingest.py — a pointer, not an engine

Why a separate file? So you can change the path and run ingest without opening bot.py. This file does not search, chunk, or call GPT. It only decides which path to hand to ingest().

Put this in your file · python — ingest.py
"""Turn company files into searchable knowledge.

Drop any .md, .txt, or .docx files in knowledge/raw/, then:

    python ingest.py

Or pass one file or folder:

    python ingest.py /path/to/your-doc.md

There is no required filename or section layout. If you ingest nothing, chat still
works — the bot just has no company files to look up.
"""

from pathlib import Path
import sys

from bot import RAW_DIR, ingest

# Default: every allowed file in knowledge/raw/. Override with a CLI path.
FILE_PATH = str(RAW_DIR)


if __name__ == "__main__":
    path = sys.argv[1] if len(sys.argv) > 1 else FILE_PATH
    if not path.strip():
        raise SystemExit("Set FILE_PATH in ingest.py, or run: python ingest.py /path/to/file.md")
    summary = ingest(path)
    print(f"Ingested {summary['files']} file(s) from {Path(path).expanduser()} into {summary['chunks']} chunks.")
  • from bot import RAW_DIR, ingest — Load bot.py (which loads .env and creates folders). RAW_DIR is knowledge/raw/.
  • FILE_PATH = str(RAW_DIR) — Default is the whole incoming folder, not one magic filename. Drop any company files there. Or pass a path on the command line.
  • sys.argv[1] if len(sys.argv) > 1 else FILE_PATH — If you ran python ingest.py some/file.md, use that. Otherwise use the folder. sys.argv is the list of words you typed after python.
  • Empty path → exit — An empty string is not a file.
  • summary = ingest(path) — All the real work.
  • Print files and chunks — If you see file and chunk counts, it worked. If the folder is empty, you get a clear error. You can still run python chat.py.
What you should run Put company files (any names) in knowledge/raw/, then python ingest.py. After it runs, open knowledge/okf/ and knowledge/okf/chunks/. To chat with no company files at all, skip ingest and run python chat.py.

chat.py — the front desk

Why so small? Because the product is reply(). The terminal is one of many possible doors. A future website will call the same function.

Put this in your file · python — chat.py
"""Talk to the bot. Edit prompt.md to change how it speaks."""

from bot import reply


def main() -> None:
    print("Type a message. Type quit to exit.")
    while True:
        try:
            text = input("you> ").strip()
        except (EOFError, KeyboardInterrupt):
            print()
            break
        if not text:
            continue
        if text.lower() in {"quit", "exit", "q"}:
            break
        result = reply(text)
        print(f"bot> {result['reply']}")
        if result["sources"]:
            print(f"sources> {', '.join(result['sources'])}")
        if result["facts"]:
            print(f"facts> {'; '.join(result['facts'])}")
        print(f"control> {result['control']}")
        if result["control"] in {"end", "handoff"}:
            break


if __name__ == "__main__":
    main()
  • from bot import reply — The only import. chat.py does not know about Chroma or LangGraph.
  • input("you> ") — Wait for you to type. Returns a string. The prompt you> is just a label so you know it is your turn.
  • EOFError, KeyboardInterrupt — Ctrl+D or Ctrl+C should exit cleanly, not dump a stack trace.
  • Empty line: continue — Do not call the API for an accidental Enter. continue means “go back to the start of the while loop.”
  • quit / exit / q — Leave without involving GPT.
  • result = reply(text) — The whole engine. result is a dict with keys reply, control, facts, sources.
  • Print those keys — So you can see RAG citations, memory, and whether the loop should stop.
  • If control is end or handoff: break — Leave the while loop. continue as a control value is different: it means “keep chatting.”
  • if __name__ == "__main__" — Run main() only when you type python chat.py, not when some other file imports chat.py.

One message, in slow motion

You can do this with or without ingest. First, no company files:

you> What are your opening hours?
  1. chat.py calls reply("What are your opening hours?").
  2. reply starts the graph with message set to that string.
  3. node_retrieve calls retrieve. With nothing ingested, knowledge is empty. history and facts are empty on the first turn.
  4. load_prompt puts “No matching knowledge yet.” where {knowledge} was.
  5. node_agent sends that to GPT. Because prompt.md says do not invent, the bot should say it does not know.
  6. route_agent sees no tool_calls → save.
  7. node_save stores both lines. Memory and tools still work on later turns.

If you had dropped a real company file in knowledge/raw/ and ingested, step 3 would return matching chunks and step 5 would answer from those pages. Citations in sources> would use that file’s name and headings.

If you type “book a demo about billing,” step 5 emits a tool call, we go to tools, book_demo inserts an actions row, then GPT writes “You’re booked.” That loop is why LangGraph exists. It does not need a handbook.

Scenario 1 — RAG (only if you ingested company files)

you> Ask something that is actually in the file you dropped in knowledge/raw/
bot> An answer drawn from those pages…
sources> your-file#SomeHeading

The heading names come from their document. If you ingested nothing, this question should get “I don’t know,” not a made-up policy. If the bot invents, check that load_prompt is filling {knowledge} and that prompt.md still says do not invent.

Scenario 2 — memory (the person, not the company)

you> My name is Sam.
facts> User’s name is Sam
you> What is my name?
bot> Your name is Sam.

That fact sat in SQLite, not in Chroma. Company RAG and person memory are two piles on purpose. Mixing them would make “Sam” look like a product name.

Scenario 3 — tool loop

you> Book a demo about billing tomorrow at 3pm.
bot> You’re booked…

If this only talks and never books, you probably missed @tool or the TOOLS list. The graph would have no function to run.

Scenario 4 — handoff / goodbye

you> I want to talk to a human.
control> handoff

chat.py stops. That is conversation control, not RAG. “Goodbye” should set control to end.

Three experiments so it sticks

  1. Add “Always answer in simple English” to prompt.md. Do not touch Python. The voice should change. That file is live.
  2. Drop any real company file in knowledge/raw/, ingest, ask a question that is in that file. Then change a sentence in the file, ingest again, ask again. The answer should follow the file. That is RAG.
  3. Open a chunk file in knowledge/okf/chunks/. Read the YAML at the top. That is OKF. You are looking at what the bot searched.

Conclusion

Company files in knowledge/raw/ are optional and unnamed. Ingest labels them (OKF) and indexes them (Chroma). retrieve picks pages. load_prompt pastes them. LangGraph orders lookup → GPT → maybe tools → save. GPT only writes. prompt.md decides manners. data/bot.db remembers the person. Skip ingest and you still have a bot — just not one that knows a company’s docs.

When you add a UI, call reply(). When you add a real calendar, change the body of book_demo. When you add a second product, put a new file in knowledge/raw and ingest. Do not rebuild the machine.
